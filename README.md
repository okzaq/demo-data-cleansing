## 何ができるか

| 入力（Before） | 出力（After） |
|---|---|
| `㈱北海道商事` / `(株)北海道商事` | `株式会社北海道商事` に統一 |
| `ｻﾄｳ ﾊﾅｺ` / `さとう はなこ` | `サトウハナコ` に統一 |
| `札幌市中央区北一条西二丁目3番4号` | `札幌市中央区北1条西2-3-4` に統一（※「五稜郭」等の地名の漢数字は保持） |
| `０６２－００２０` / `0620020` | `062-0020` に統一 |
| 同一人物が2行に重複 | 名寄せグループIDを付与して統合候補を提示 |
| 同姓同名だが別人の可能性がある行 | **「保留」アラート**を出して人間の確認に回す |

## 設計方針: AI任せにしない

すべてをAIに判定させるのではなく、役割を3段階に分けています。

```
CSV入力
  │
  ├─ ① ルールベース整形（normalize.py）
  │     決定的に直せる表記揺れはコードで処理。AIコスト・ゆらぎゼロ
  │
  ├─ ② ルールで確実な統合（matching.py）
  │     メール完全一致・電話一致＋名前類似 などは即マージ
  │
  ├─ ③ 曖昧なペアのみ AI 判定（ai_judge.py / Claude API）
  │     確信度 0.85以上 → 統合
  │     確信度 0.5〜0.85 → 「保留」として人間の確認に委ねる
  │     確信度 0.5未満  → 別エンティティと判定
  │
  └─ 出力: 整形済みCSV（名寄せグループID・要確認フラグ付き）
```

誤った統合（別人を同一人物として結合）は誤った分割より重大な事故になるため、
AIには「確信が持てないものを保留にする」役割を持たせています。

## 技術構成

- **バックエンド**: Python 3.12+ / FastAPI
- **AI判定**: Claude API（Anthropic）— コスト最適化のため Haiku モデルを使用し、
  曖昧ペアのみをバッチで1リクエストにまとめて判定
- **フロントエンド**: 素のHTML/JavaScript（依存なし）
- **デプロイ**: Vercel（サーバーレス）
- **コスト保護**: IPごとのレート制限（30回/日）・入力上限500行・512KB

APIキー未設定の環境では、AI判定部分がモックで動作します（開発・検証用）。

## ローカルで動かす

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
# → http://localhost:8000
```

Claude APIによる実判定を試す場合は環境変数を設定します（未設定ならモック判定）。

```bash
# .env.example を参考に
export ANTHROPIC_API_KEY=sk-ant-...
```

テスト（APIキー不要）:

```bash
python tests/test_pipeline.py
```

## サンプルデータについて

`data/` の顧客・施設データはすべて**架空**です（実在の人物・法人・施設とは関係ありません）。
国や自治体が公開するオープンデータ（施設一覧・法人一覧など）と同様の構造・「汚れ方」を想定して作成しています。
